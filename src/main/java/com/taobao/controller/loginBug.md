为何重启服务后，刷新原有的主页面跳转到的重定向的登陆界面即使用正确的账号密码也会出错？
    主要原因：残留的旧 Cookie（可能性最大）
    重启服务前，浏览器里存着上一次的会话凭证 JSESSIONID(存在cookie内)。 
    但重启后，服务端内存中的 Session 已经被清空了，旧的 JSESSIONID 已经失效，
    而新登录页的 js 可能依然拿着这个失效的凭证去访问了登录接口。
    这会导致后端拦截器返回 401，前端可能在没完全刷新登录状态的情况下就跳转到了登录页。
    此时如果你直接登录，由于传过去的 JSESSIONID 依然指向一个不存在的会话，后端可能会表现异常。

解决方法：
    最简单彻底的办法就是，每次重启项目后，使用 无痕模式（隐私窗口） 测试，
    或者在登录前清除浏览器的全部 Cookie（F12 -> Application -> Cookies -> Clear）。
